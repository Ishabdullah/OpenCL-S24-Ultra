New experiment, independent of historical reports. Order: **64 → 80 → 96 → 96 → 80 → 64** slots; budgets **2560 / 3200 / 3840 MiB**, respectively, four CPU threads throughout. The output-token maximum is deliberately fixed at **64 for every pass**: this isolates cache capacity rather than varying trajectory length alongside slots. Same existing GGUF, prompt, seed, sampling and synchronized-forward timing as the established benchmark. The first pass freezes the logits and teacher tokens and has zero comparisons; each subsequent pass must bit-match every evaluated position. Forward measurements include cache operations and storage reads; sampling, setup, monitoring and cooling are outside forward timing. Compare pooled decode rates by slot count as well as chronological pairs; two repetitions do not establish generality across prompts/devices.
