# Controlled four-thread cache capacity comparison (prepared; not run)

New experiment, independent of historical reports. Order: **64 → 80 → 96 → 96 → 80 → 64** slots; budgets **2560 / 3200 / 3840 MiB**, respectively, four CPU threads throughout. The output-token maximum is deliberately fixed at **64 for every pass**: this isolates cache capacity rather than varying trajectory length alongside slots. Same existing GGUF, prompt, seed, sampling and synchronized-forward timing as the established benchmark. The first pass freezes the logits and teacher tokens; each subsequent pass must bit-match every evaluated position. Forward measurements include cache operations and storage reads; sampling, setup, monitoring and cooling are outside forward timing. Compare pooled decode rates by slot count as well as chronological pairs; two repetitions do not establish generality across prompts/devices.

Initial cooling and five interpass pauses target at least 180 seconds, with soft ceilings battery 40°C / CPU 55°C / HTP 50°C and a 300-second target cap. The existing cooldown helper only stops at an untimed complete-pass boundary; its polling can miss a boundary, so **do not interpret a run without five recorded cooling events as a controlled comparison**. The runner rejects such a run, supervisor failure, bad replay, or watchdog stop. It samples /proc MemAvailable, child RSS, VmSwap and smaps_rollup PSS/Swap outside forward timing into memory.jsonl (timestamps allow joining to thermal stages/pass log); unavailable fields are null, not zero. Thermal monitor records temperatures and the benchmark records per-pass storage bytes and cache log counters. Hashes cover runner, benchmark/cache sources, cooling and thermal tools, analyzer, patch and binaries. The runner reads the entire source file before computing its hash, then writes that digest to a separate provenance.json; hashing the runner itself is not a circular write. Model identity is path and size, not a full GGUF hash (hashing the huge model could disturb the thermal baseline). Record model checksum separately if needed before cooling.

No physical run attempted here: six inference passes plus 18–30 minutes of cooling and setup demand an attended device and can encounter background memory pressure; the prior cooled run had only 1.25 GiB minimum free. Before running, check free disk, battery/power, model and binaries, and remain present to stop on pressure or interruptions. No installer defaults, pins or historical runners were changed. This script writes evidence exclusively in this directory and refuses to overwrite an existing run. Exact command from repository root:

```sh
python reports/2026-10-13/cache-64-80-96-four/run-benchmark.py --run
# After successful run:
python scripts/analyze-moe-cache-sweep.py reports/2026-10-13/cache-64-80-96-four
```
