# Experimental 7B registration and phase handoff

These are opt-in research snapshots, not installer defaults. Do not apply them to the managed `.work-npu` installation or the original `~/llama.cpp`.

Start from upstream `e358d59178377be4c58ba567925e05faadbccb57` plus this project's root `patches/llama.cpp-hexagon-sphal.patch`, in a separate checkout/build. `registration-hybrid.patch` was generated from the actual isolated working source against local NPU checkpoint `53d539ccc327858498c055909d19468954b90531`. A read-only `git apply --check` passes against the fresh NPU installer's patched source. Passing that check is not a new clean-room build test.

The combined patch changes nine files: `include/llama.h`, context/model/model-loader/KV source and headers, and `ggml/src/ggml-hexagon/ggml-hexagon.cpp`. It combines retained canonical GGUF weight mappings, a one-way KV migration/CPU-only scheduler API, a plain non-SWA LLAMA architecture guard, and an opt-in idle-weight FastRPC registration window. Existing Qwen2/Qwen3 handoff support remains. The separate `registration-window.patch` is an alternative window-only snapshot: do not apply it together with the combined patch.

The native prototype reused unchanged known-good objects and the unchanged v75 DSP binary. Build argument arrays and hashes are in the data directory. This is not a standalone installer reproduction: a full fresh native/DSP build with the patch and helper is still required before integrating it into installation. No binary objects are distributed. The two new helper variants contain post-load thermal admission and a canonical CPU-repack control; the earlier helper is retained to identify the numerical qualification run precisely.

Tested experimental runtime settings: `GGML_HEXAGON_REGISTRATION_WINDOW=2048`, `GGML_HEXAGON_MBUF=512`, `GGML_HEXAGON_VMEM=3200`, profiling OFF, six CPU threads, FA ON/F16 KV. Each process sets library search paths to its own build/bin directory and `ADSP_LIBRARY_PATH` to its own v75 DSP directory. A specific own-bin `libc++_shared.so` link corrected over-stripped runtime paths; never globally append `$PREFIX/lib`. These settings are recorded evidence, not a recommendation for arbitrary model sizes/devices.

The handoff holds the same context/model and sequence positions, copies allocated accelerator KV buffers to CPU, switches weight tensor backing to original mapped GGUF shadows, and installs a CPU-only scheduler. `GGML_PERF_HYBRID_CHECK_COPY=1` byte-checks KV for numerical qualification; leave it off for clean performance timings. Mapped weights can page in after switching, so report switch plus first decode and total response time. The API is one-way; it does not restore released NPU weights for a later accelerator prefill and is not a production multi-context scheduler.

`manifest.json` records the base and patch check. `../data/export-provenance.json` records exact source and exported file hashes; `../SHA256SUMS` covers this published snapshot. No SDK/compiler/vendor library, model or generated executable is included.
